# 모집 공고 묶기

모집 채널 수집함에서 2~10개 공고를 선택한 뒤 **선택한 공고로 콘텐츠 만들기**를 누른다. 제목과 묶는 기준은 선택 사항이다. 원래 공고를 병합하거나 지우지 않고 별도 검토용 콘텐츠를 만든다. 선택 바구니는 채널별로 유지되며 페이지 이동과 목록 갱신으로 사라지지 않는다.

공고별로 공개 본문과 첨부를 확보하고 지원 대상·지역 조건·학생 접수·학교/교사 추천 일정을 각각 추출한다. 연결된 요약 AI가 없으면 읽은 자료를 보관하고 조건 정리 대기로 표시한다. 기존 글쓰기 도우미는 서버에 저장한 묶음 자료를 자동 참조하며, **비교 자료 전체·원고 요청 복사**로 GPT에서 이어 쓸 수도 있다.

## 원문과 근거

- GED 공개 다운로드 팝업의 `fn_down` 인자를 해석한다. 동일 호스트의 실제 다운로드 응답이 PDF인지 검사한다.
- 최대 3개 PDF, 파일당 8MB·80쪽, 합계 80,000자와 공유 24초 한도 안에서 읽는다. 실제 페이지별 텍스트와 파일/텍스트 해시를 보존한다. 스캔·잘림·미확보·HWP/ZIP은 확인 필요로 표시한다.
- 서로 다른 기관의 조건을 하나의 `organization/audience/schedules`에 합치지 않는다. 행별 자료를 보존하고, 지원 가능 여부나 전체 기관을 전수 수집했다는 주장을 만들지 않는다.
- 원문이 바뀐 뒤 과거 추출 조건을 재사용하지 않는다. 기존 묶음 자체를 다시 선택하면 원래 개별 공고를 선택하도록 안내한다.
- 카드 한 편에 담기 어려운 분량은 원문과 비교 자료를 유지한 채 나누어 편집하도록 알린다. 작성에 필요한 자료가 200,000자를 넘으면 모델 호출 전에 묶음을 나누도록 안내한다.

## 처리와 복구

`POST /channels/:cid/notice-bundles`는 요청 UUID로 중복 생성을 막고 `notice_bundle` 작업을 등록한다. 한 실행에서 공고 한 건을 처리한 뒤 진행을 저장한다. 초기 원고의 `noticeBundle.jobId`로 창을 닫아도 상태를 다시 조회한다. 진행 조회에는 큰 PDF 본문을 반복 전송하지 않는다.

원본 콘텐츠와 원고 버전은 수정하지 않는다. 공유 원문 문서의 공개 본문 캐시는 갱신될 수 있다. 공고별 유료 분석은 최대 한 번이며, 정지·취소·임대 만료·서버 종료에서 중단한다. 완료 여부가 불명확한 유료 요청은 자동 반복하지 않는다. 일부 자료를 읽지 못해도 해당 행과 사유를 남기며 자동 발행하지 않는다.
